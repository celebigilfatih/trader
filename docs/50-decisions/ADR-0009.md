# ADR-0009: Stochastic API seçicisinin skaler %K eşlemesi

- **Status:** Accepted
- **Date:** 2026-11-06
- **Owners / approvers:** Ürün sahibi; somut A onay sorusuna 2026-11-06
  “Sıradaki Adım ile devam edelim.” yanıtı.
- **Supersedes / superseded by:** N/A
- **Related:** OS-01, ADR-0002, M1-P0-01,
  [inceleme ve kabul kaydı](../20-execution/2026-11-06-stochastic-api-design.md)

## Context

`GET /api/v1/analysis/{symbol}?indicators=stoch` seçiciyi kabul eder; gerçek
`TechnicalAnalyzer` ise `stoch_k` ve `stoch_d` serilerini üretir. Route seçici
adıyla seri aradığı için `KeyError('stoch')` oluşur. Kontrollü provider + gerçek
hesaplayıcıyla HTTP 500 tekrarlandı; mevcut analyzer double'ı seçici adıyla seri
ürettiğinden eski API testleri bu hatayı yakalamaz.

Mevcut API okuyucusu seçilen ad altında `float | null` skaler yanıt üretir.
MACD'nin ana serisi bu biçimde döner; signal/histogram kendiliğinden eklenmez.
Ancak `stoch` skalerinin %K mı %D mi olduğu repository sözleşmesinde tanımlı
değildir. Legacy `stoch_k/stoch_d` üretimini değiştirmek gerekli değildir.

AGENTS, “veri modeli/migration” değişikliğinde açık onay ister. Alan adı ve
türü korunsa da seçicinin ilk kez belirli bir seriye anlamlandırılması burada
bu kapı kapsamında bir veri sözleşmesi kararı olarak değerlendirildi. Bu
eşlemenin onaya sunulması protokolün bu duruma yorumudur; genel devam talebi
özel eşlemeye önceden verilmiş onay sayılmaz. Yeni endpoint/tablo/migration yoktur.

## Decision Drivers

- Desteklenen seçicide hesaplama tamamlandığı halde API 500 oluşmamalı.
- Mevcut seçici → tek skaler/null yanıt biçimi ve diğer seçiciler korunmalı.
- Gerçek sıfır ile henüz hesaplanamayan NaN ayrılmalı.
- Core config/formül/legacy serileri ve kimlik/provenance davranışı aynı kalmalı.

## Considered Options

| Seçenek | Sonuç / ödünleşim |
|---|---|
| **A — `stoch` altında %K (önerilen)** | Mevcut skaler biçimini korur. `ta.momentum.stoch` zaten %K üretir; %D ayrı yumuşatılmış seridir. Dar API adaptör eşlemesi yeterlidir. Bu endpoint %D vermez. |
| B — `stoch_k/stoch_d` alanları veya nested nesne | İki çizgiyi de açar; seçilen ad altında tek skaler davranışını değiştirir, response alanı/türü ve okuyucu tasarımı ayrıca gerekir. OS-01 için gerekli değildir. |
| C — `stoch` seçimini 400 ile reddetmek | Hesaplayıcının mevcut yeteneğini API'den kaldırır; seçici config'de desteklenirken işlevi azaltır. Önerilmez. |

## Decision

**Accepted — A seçeneği.** Kullanıcıya `stoch = %K` eşlemesi somut olarak
sunulup “Bu eşlemeyi onaylıyor musunuz?” soruldu. Ardından gelen “Sıradaki Adım
ile devam edelim.” yanıtı, bu tek karar bağlamında A'nın uygulanmasına onay
olarak kaydedildi. Bu kayıt önceki, öneri sunulmadan verilmiş genel devam
taleplerini geriye dönük onay saymaz; başka çoklu çıktı veya MVP genişlemesini kapsamaz.

Yalnız analiz API adaptörü `stoch` seçicisini mevcut
`stoch_k` serisine eşler. Dış yanıt anahtarı **`stoch`**, değer son bardaki
**%K** olur. `stoch_d` hesaplayıcıda kalır; bu endpoint'e yeni alan eklenmez.
Diğer seçicilerin seri araması ve mevcut `_safe_float` dönüşümü korunur.
Genel `.get(..., None)` fallback'iyle bilinmeyen eşleşme kusurları gizlenmez.

Örnek: gerçek fixture'da son K=75, D=200/3 iken beklenen sonuç:

```json
{"indicators": {"stoch": 75.0}}
```

Bu yalnız `data` içindeki ilgili parçadır; mevcut `symbol/period/interval/as_of`,
`price`, metadata ve correlation sözleşmesi korunur. K=0 ise `0.0`, warmup veya
sıfır fiyat aralığından K=NaN ise mevcut dönüşümle `null` döner; sıfır uydurulmaz.
Karışık istekte yalnız istenen seçiciler döner. `stoch_k/stoch_d` query seçicileri
eklenmez; mevcut 400, kimliksiz isteğin 401 davranışı korunur.

## Consequences

- OS-01 HTTP 500 → seçilen ad altında hesaplanmış %K veya null olur.
- Bu eşleme kâr, al/sat eşiği, yeni indikatör veya finansal politika seçmez.
- Scalar API'den %D isteyen istemci için ayrı, onaylı genişleme gerekir.
- Diğer çoklu çıktı seçicilerinin destek/anahtar envanteri bu dar işin genel
  çözümü sayılmaz. Legacy serileri veya global analyzer getter'ı değiştirilmez.
- Auth/provider/veri lisansı/CI/bağımlılık/kalıcı şema/deployment değişmez.

## Rollout and Rollback

Gerçek analyzer + fixture provider ile HTTP regresyonu önce
200/%K beklentisinde assertion failure vermelidir; ardından tek adaptör eşlemesi
uygulanır. K≠D örneği, sıfır, null, karışık seçim, metadata ve 400/401 sınanır.
Hedef API/momentum ve tam çevrimdışı backend paketi yeniden çalıştırılır.

Geri dönüş yalnız adaptör eşlemesini/testini geri alır; kalıcı veri veya model
artifact'ı etkilenmez. Eski `stoch` hatası yeniden ortaya çıkacağı açıkça
raporlanır; rollback, kusurun giderildiği anlamına gelmez.
